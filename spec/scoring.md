# Scoring — Gap Matrix 사분면 판정 규칙

버전: 1.2.0 · 선행 문서: `plane-a-visibility.md`, `plane-b-readiness.md`

이 문서는 AVI(0~100)와 ARS(0~100)를 각각 이분해 사분면을 확정하는 규칙만 다룬다.
각 지수의 산출 자체는 선행 문서에 있다.

---

## 1. 임계값 (v1 고정)

```yaml
AVI_THRESHOLD: 25    # AVI ≥ 25  → high
ARS_THRESHOLD: 60    # ARS ≥ 60  → high
```

두 값 모두 **경계 포함(≥)이 high**다.

| | ARS < 60 | ARS ≥ 60 |
|---|---|---|
| **AVI ≥ 25** | **Q3** 브랜드 관성형 | **Q1** 리더 |
| **AVI < 25** | **Q4** 미개척 | **Q2** 준비만 된 상태 |

사분면 id와 라벨은 `report.schema.json`의 `gap_quadrant` enum과 일치한다.
각 사분면의 처방은 `avr-model.md` §4.1에 있다.

---

## 2. ARS 컷오프 60의 근거

ARS는 rubric 기반 결정론적 점수이므로 임계값을 구조에서 유도할 수 있다.

**(1) 균일 부분충족선이 50점이다.**
모든 항목이 1점(부분 충족)이면 `raw_ARS = 0.5 × 100 = 50`이다 — **항목 수와 무관하다.** Pillar 가
채점 항목 수로 정규화하므로 1/2 = 0.5 가 모든 Pillar 에서 성립한다.
따라서 50은 "전 항목을 어중간하게 했을 때"의 좌표다. 이 상태를 "준비됨"이라고 부를 수 없다.
임계값은 반드시 50을 넘어야 한다.

**(2) 60은 "다수 항목이 2점"을 요구하는 최소선이다.**
가중치를 무시하고 단순화하면, ARS 60은 전체 항목 정규화 평균 0.6 —
즉 **1점 항목보다 2점 항목이 더 많아야** 도달한다.
(예: 2점 44%·1점 32%·0점 24% → 0.60)
"부분적으로 했다"와 "했다"를 가르는 자연스러운 지점이다.

**(3) 게이팅 상한 40과 20점 마진을 둔다.**
`gating.max_score_when_blocked = 40`이므로, 게이팅 발동 브랜드가 ARS-high로
분류되는 일은 어떤 경우에도 발생하지 않는다. 임계값을 45~50까지 낮추면
게이팅 상한과 너무 가까워져 이 안전 여백이 사라진다.

**(4) P1·P2만 잘해도 넘을 수 있어서는 안 된다.**
P1(25) + P2(25) = 50. 두 Pillar를 만점 받아도 50점이므로 60을 넘지 못한다.
**P3·P4·P5에서 최소 10점 이상을 확보해야만 high로 분류된다.**
이것은 의도된 설계다 — "사이트 기술만 정리하면 준비 완료"라는 흔한 오해를 점수 구조로 차단한다.

### 2.1 관측 (2026-09-16) — 설계 의도가 실제로 작동한다

§6-1 은 임계값 논의에 **코호트 표본 수와 분포**를 요구한다. 그 데이터를 여기 기록한다.
임계값을 바꾸자는 제안이 **아니다** — 위 (1)~(4)가 의도한 대로 작동하는지 확인한 것이다.

| | 값 |
|---|---|
| 코호트 | 국내 28곳, 측정 성공 **27곳** |
| ARS 중앙값 | **42.1** (평균 42.3, 범위 30.6~66.0) |
| ARS ≥ 60 | **2/27** |
| ARS ≥ 50 | 4/27 |

**(4)의 예측이 그대로 나왔다.** 같은 27곳을 `P1`(1층 도달)만으로 재면 중앙값 57.1 ·
60 이상 11/27(41%)이고, 여기에 "있으면 만점"(0/1/2 를 있다/없다로) 규칙까지 적용하면
중앙값 71.4 · 60 이상 22/27(81%)이 된다. 즉 **"1층만 + 품질 무시"가 이 코호트를
'대부분 60 이상'으로 만든다.** §2(4)가 차단하려던 바로 그 상태다.

> ⚠️ **이 코호트는 선택 편의가 있다.** "AEO 작업을 한 것으로 알려진" 브랜드 목록이지
> 국내 사이트의 평균이 아니다. 여기서 "국내 사이트의 절반이 40점대" 같은 문장을
> 유도하면 안 된다. 모집단 추정이 아니라 **이 27곳의 관측**이다.

> ⚠️ 이 분포는 **임계값의 타당성을 입증하지 않는다.** 60이 "실제로 인용되는 상태"를
> 가르는지는 Plane A 결과와 대조해야 알 수 있고(`avr-model.md` §6), 그 회귀는 아직
> 돌지 않았다. 여기 적은 것은 분포일 뿐이다.

> 🚫 **그리고 이 코호트로는 그 대조를 할 수 없다.** 28곳이 전부 다른 카테고리라
> 인용률의 기저가 섞이고, 3곳 이상인 카테고리는 AEO 대행 하나뿐인데 그 셋은 전부
> 상위권이라 예측변수의 분산도 없다. 전제와 조건은
> `plane-a-visibility.md` §6.4 에 있다 — **다른 코호트를 새로 구성해야 한다.**

출처: `docs/BASELINE_28.md`(수정 전 대조군) · `docs/REMEASURE_28.md`(수정 후 3회차).
두 문서는 비공개 저장소에 있고, 이 표의 숫자는 백엔드 시험이 그 문서와 대조한다.

## 3. AVI 컷오프 25의 근거

**AVI 임계값은 ARS와 달리 구조에서 유도되지 않는다. 시장 관측에 기반한 추정치다.**
이 사실을 리포트에 명시한다.

### 3.1 유도

AVI 25는 대략 다음 상태에 대응한다 (α=0.5, β=0.3, γ=0.2 적용):

```
MR = 0.33,  PosScore = 0.15,  CitShare = 0.10
→ 0.5(0.33) + 0.3(0.15) + 0.2(0.10) = 0.165 + 0.045 + 0.020 = 0.230 → AVI 23.0

MR = 0.35,  PosScore = 0.18,  CitShare = 0.12
→ 0.175 + 0.054 + 0.024 = 0.253 → AVI 25.3
```

즉 **"목표 질문 3개 중 1개에서 언급되고, 가끔 상위에 오르며, 인용은 드물게 발생하는 상태"**
가 대략 25다.

기준점으로 삼은 관측치는 GPTO가 자사 유료 고객 코호트에 대해 공개한 평균 SMR 35.4%
(내부 시장 분석 §2.3, 비공개)다. 이는 **이미 AEO에 투자 중인 브랜드들의 평균**이므로,
"양호"의 하한선으로 삼기에 적절한 참조점이다.
PosScore와 CitShare는 일반적으로 MR보다 상당히 낮게 관측되므로 위와 같이 보수적으로 잡았다.

### 3.2 한계와 재캘리브레이션 계획

이 컷오프의 약점을 숨기지 않는다:

1. **GPTO의 35.4%는 독립 검증되지 않은 자사 발표 수치**이고, 질문 세트 설계와 채널 구성이
   본 프레임워크와 다르다. 직접 비교 가능한 값이 아니다.
   표본은 공시되어 있다(매칭쌍 3,141개, 2026-09-10 확인). 다만 **클러스터 구조(ρ)와
   질문 세트가 공개되지 않아 n_eff 를 계산할 수 없으므로**, 이 값에는 우리 기준의
   신뢰구간을 붙일 수 없다. 참조점으로만 쓰고 비교 대상으로 쓰지 않는다 (plane-a §3.4).
2. AVI 절대 수준은 **질문 세트 난이도에 강하게 의존한다.** 브랜드명을 포함한 질문을 넣으면
   MR이 인위적으로 올라간다. 따라서 질문 세트 설계 규약이 고정되기 전까지 컷오프는 잠정값이다.
3. **산업별 baseline이 다르다.** 카테고리 경쟁 밀도가 높을수록 개별 브랜드 MR은 구조적으로 낮다.

**재캘리브레이션 규칙**:
- 파일럿 10개 사이트(내부 파일럿 기록, 비공개) 완료 시 컷오프를 재검토한다.
- 동일 산업 코호트 표본이 **30 브랜드 이상** 확보되면 고정값 25를 폐기하고
  **산업별 코호트 중앙값**을 임계값으로 전환한다. 그때까지는 25를 사용하고
  리포트에 "절대 기준이 아닌 잠정 컷오프"임을 표기한다.
- 컷오프를 변경하면 과거 리포트의 사분면 판정이 바뀐다. `rubric_version`과 별도로
  `scoring` 규칙 버전을 리포트에 남기고, 소급 재판정 여부를 명시한다.

## 4. 경계 사례 규칙

### 4.1 AVI 신뢰구간이 임계선을 걸치는 경우

AVI에는 표본 오차가 있다(`plane-a-visibility.md` §3). 점추정만으로 사분면을 확정하면
**표본 잡음이 처방을 뒤바꾼다.** 다음 규칙을 강제한다.

```
if avi_ci.lower < AVI_THRESHOLD <= avi_ci.upper:
    gap_quadrant.borderline = true
```

`borderline = true`일 때:
1. 사분면 id는 점추정 기준으로 채우되, **리포트 UI에서 단일 사분면으로 단정하지 않는다.**
2. 상하 인접 두 사분면의 처방을 **함께** 제시한다.
   (예: AVI 점추정 26, CI 21~31, ARS 72 → Q1과 Q2 처방 병기)
3. 두 처방의 **공통 항목을 먼저 실행**하도록 우선순위를 재정렬한다.
4. 표본 수를 늘린 재측정을 1순위 권고로 넣는다.

ARS는 **표본 오차**가 없다 — 사이트를 표본추출하지 않고 항목을 직접 채점하기 때문이다.
그래서 Wilson 구간이 붙지 않는다. **그러나 커버리지 불확실성은 있고, 그것은 확정적으로
계산할 수 있다** — §4.1-1 의 확정 구간이 그것이다. 아래 `borderline` 플래그는 그
불확실성의 **불리언 요약**이고, 확정 구간은 같은 사실의 **정량 표현**이다:

```
if plane_b.coverage.scored_items / plane_b.coverage.judgeable_count < 0.7:
    gap_quadrant.borderline = true
```

**분모는 `total_items`가 아니라 `judgeable_count`다 (v1.1.0~).** `judgeable_count`는
`total_items`에서 `unavailable_kind`가 `not_applicable`·`design_limit`인 항목 수를 뺀
값이다(`plane-b-readiness.md` §8.4). 이 두 kind는 "이 사이트에 애초에 해당하지 않는다"는
뜻이지 "확인하지 못했다"는 뜻이 아니므로, 그런 항목이 있다고 해서 ARS의 신뢰도가 낮아지는
것은 아니다. 반대로 `inconclusive`·`no_collector`·`input_missing`은 여전히 분모에 남으므로
"모르는 것"은 그대로 불확실성으로 반영된다. `not_applicable`·`design_limit`이 전혀 없는
진단은 `judgeable_count == total_items`이므로 이 재정의는 v1.0.0 시점의 결과를 바꾸지 않는다.

무료 티어(P4 미채점, 31/44 = 70.5%)는 이 경계를 아슬아슬하게 넘지만,
P4를 통째로 못 본 상태에서 Q2/Q4를 구분할 수 없으므로 무료 리포트는
**항상 `borderline = true`로 강제**하고 "권위 진단 없이는 Q2와 Q4를 구분할 수 없음"을 명시한다.


### 4.1-1 ARS 확정 구간 (Determinate Band) — v1.2.0

**신뢰구간이 아니다.** 표본에서 모수를 추정하는 것이 아니라, **미관측 항목이 가질 수
있는 값의 범위에서 ARS 가 취할 수 있는 최솟값과 최댓값을 직접 구한다.** rubric 이
항목 점수를 `{0, 1, 2}` 로 고정해 두었으므로(`scoring.yaml: item_levels.max_level`)
이 경계는 **가정 없이 유도**되며, 분포 가정도 유의수준도 필요 없다.

#### 정의

`U` = 미관측 항목 중 **판정 대상인 것**의 집합. 즉 채점되지 않았고
`unavailable_kind` 가 `not_applicable`·`design_limit` **이 아닌** 항목이다.
(그 두 kind 는 "이 사이트에 성립하지 않는다"는 뜻이라 `judgeable_count` 에서 이미
빠지고, 밴드에도 기여하지 않는다 — §4.1 의 분모 규칙과 같은 근거다.)

```
ARS_floor    = ARS( 관측된 점수 ∪ { i ↦ 0 : i ∈ U } )
ARS_ceiling  = ARS( 관측된 점수 ∪ { i ↦ 2 : i ∈ U } )
확정 구간     = [ARS_floor, ARS_ceiling]
밴드 폭 W    = ARS_ceiling − ARS_floor
```

`ARS(·)` 는 §5 의 판정 의사코드와 **같은 함수**다. 밴드는 별도 산식이 아니라 같은
산식을 두 번 평가한 것이다 — 그래서 커버리지 재정규화·Pillar 제외·게이팅이 모두
그대로 적용되고, 구현이 두 벌로 갈라질 여지가 없다.

`U = ∅` 이면 `ARS_floor = ARS = ARS_ceiling` 이고 `W = 0` 이다.

#### 무엇을 뜻하는가

**W 는 "우리가 보지 못한 것에 점수가 얼마나 의존하는가" 다.** 점수 자체가 아니라
**진단의 완결성**을 재는 값이다. W 가 크면 그 리포트는 사이트에 대해 말하기보다
우리 관측의 한계에 대해 말하고 있는 것이다.

실측(2026-09-21, 국내 코호트 27곳, 자동 티어): W 중앙값 **38.9점**, 최소 11.9,
최대 53.0. **ARS ≥ 60 을 확정할 수 있는 사이트는 0곳**이었다 — 자동 진단만으로는
`ARS_floor ≥ 60` 을 만들 수 없다는 뜻이고, 이는 `plane-b-readiness.md` §11 이 서술한
자동 티어의 도달 범위와 같은 사실의 정량 표현이다.

#### 해소 분해 (Resolution Decomposition)

밴드를 그대로 내보내면 "이 도구는 아무것도 확정하지 못한다" 로 읽힌다. 그건 사실이지만
**쓸모 있는 형태가 아니다.** `U` 의 원소는 `unavailable_kind` 에 따라 **해소하는 행동이
다르므로**, 밴드를 행동별로 분해한다.

| kind | 해소 행동 |
|---|---|
| `awaiting_manual` | 심화 진단(사람 판정) |
| `input_missing` | 고객이 입력 제공 (질문 세트·문서 목록 등) |
| `inconclusive` | 재시도 또는 인프라 개선 |
| `no_collector` | 참조 구현의 로드맵 |

행동 `a` 를 실행하면 그 kind 의 항목이 `U` 에서 빠지므로 밴드가 좁아진다.

```
W(∅)        = 지금의 밴드 폭
W(A)        = 행동 집합 A 를 실행한 뒤의 폭
정보 이득 G(a) = W(∅) − W({a})      ← 행동 a 가 없애는 불확실성, 단위는 ARS 점수
```

> ⚠️ **해소 후에는 폭만 낸다. 경계(floor·ceiling)는 내지 않는다.**
>
> 행동을 실행하면 그 항목은 *관측될* 뿐 **어떤 값이 나올지는 모른다.** 그래서
> 해소 후의 경계는 미지의 값 `v` 에 따라 통째로 이동한다. 반면 폭은 `v` 가 소거되어
> **정확히 계산된다** — 항목 수가 분모에 들어갈 뿐 값이 들어가지 않기 때문이다.
>
> ```
> W(A) = Σ_p  w_p · |U\A ∩ p| / n_p        (n_p 는 그 pillar 의 **판정 대상 항목 수**)
> ```
>
> 수식에 `v` 가 없다. **`n_p` 는 해소 여부와도 무관하다** — 남은 미관측 항목도 경계
> 계산에서 `0`/`max_level` 을 할당받으므로 분모에 들어가기 때문이다. 초안에서 이 점을
> 틀려 `n_p` 를 해소 후 개수로 놓았고, 골든 케이스
> `band-resolution-reports-width-only-not-bounds` 가 그 대수 오류를 잡았다 —
> 기대값을 구현에 맞춘 것이 아니라 손 계산을 다시 해 구현이 옳음을 확인했다.
>
> 해소 후 경계를 내려면 미지의 값을 가정해야 하고, **가정을 넣는 순간 이 지표는
> 확정 구간이 아니라 추정치가 된다.** 그러면 이 절의 존재 이유가 사라진다.

**`G(a)` 가 이 프레임워크의 고유 산출이다.** "심화 진단을 받으면 무엇이 좋아지는가" 에
마케팅 문구가 아니라 **점수**로 답한다. 실측(GPTO, 2026-09-21):

```
지금 (자동 진단만)      [40.0, 77.6]   W = 37.6      ← 경계는 여기서만 확정이다
심화 진단(사람)을 받으면                W ≈  9.4      G = 28.1
+ 고객 입력을 받으면                    W ≈  5.0      G =  4.4
+ 재시도가 성공하면                     W ≈  2.5      G =  2.5
```

**경계가 찍힌 줄은 첫 줄뿐이다.** 나머지는 폭과 이득만 낸다 — 위 경고의 이유다.

#### 표기 규칙 (강제)

```
ARS 57.2  ·  확정 구간 [40.0, 77.6]  (미관측 14항목, 폭 37.6)
           ·  심화 진단을 받으면 폭 9.4 로 (−28.1)
```

1. **점추정을 없애지 않는다.** 구간만 내면 경쟁 비교와 시계열이 불가능해진다.
2. **`W = 0` 이 아니면 구간을 반드시 함께 낸다.** 점추정 단독 표기는 금지다.
3. 미관측 항목 수를 함께 적는다. 폭만 보면 원인을 알 수 없다.
4. `G(a)` 를 낼 때는 **어떤 행동인지 이름을 적는다.** "구간이 좁아집니다" 로 끝내면
   고객이 무엇을 사야 하는지 알 수 없다.

#### 출력 계약 (리포트 칸 이름)

명세의 기호와 리포트의 칸을 **1:1 로** 못박는다. 이걸 적지 않으면 같은 산식을
구현한 제3자가 다른 이름으로 내보내고, 두 리포트를 기계로 대조할 수 없게 된다.
정본은 `framework/schema/report.schema.json` 의 `$defs.determinate_band` 다.

| 기호 | 칸 | 형 | 비고 |
|---|---|---|---|
| `ARS_floor` | `determinate_band.floor` | number 0~100 | |
| `ARS_ceiling` | `determinate_band.ceiling` | number 0~100 | |
| `W` | `determinate_band.width` | number ≥ 0 | `ceiling − floor` |
| `U` | `determinate_band.unobserved_item_ids` | string[] | `not_applicable`·`design_limit` 은 빠진다 |
| — | `determinate_band.resolutions[]` | object[] | 행동별 분해 |
| `a` | `resolutions[].kind` | `unavailable_kind` | 해소 대상 |
| — | `resolutions[].resolved_by` | string | 행동의 이름 (표기 규칙 4) |
| `W({a})` | `resolutions[].width` | number ≥ 0 | |
| `G(a)` | `resolutions[].information_gain` | number ≥ 0 | |
| `\|U ∩ a\|` | `resolutions[].item_count` | integer ≥ 1 | |
| — | `resolutions[].reliability` | string \| null | 이 행동 **자체의** 신뢰도 공시 (`reliability.md` §3.4). 사람이 판정하는 행동에만 붙는다 |

> **`reliability` 를 왜 여기에 두는가.** `awaiting_manual` 행은 "심화 진단을 받으면
> 폭 0" 이라고 말한다. 그건 *값을 보게 된다* 이지 *본 값이 판정자마다 같다* 가 아니다 —
> 확정 구간은 관측의 축, 판정자 일치도는 판정의 축이다. 두 문장을 갈라 두지 않으면
> 고객은 하나로 읽고, 재지도 않은 일관성을 산 것이 된다 (`reliability.md` §3.4).

`resolutions[]` 에 `floor`·`ceiling` 칸은 **없다.** 스키마가
`additionalProperties: false` 로 막고 있으므로, 경계를 실어 보내려는 구현은
검증에서 거부된다 — 위 경고를 문서가 아니라 계약으로 강제한다.

#### 이 구간이 말하지 **않는** 것

- **타당도와 무관하다.** 밴드는 "ARS 가 이 범위 안에 있다" 이지 "그 ARS 가 옳다" 가
  아니다. ARS 가 실제 인용을 예측하는지는 여전히 미검증이다 (§2.1).
- **W 가 작다고 좋은 사이트가 아니다.** W 는 진단의 완결성이지 사이트의 품질이 아니다.
- **측정 재현성과 다른 것이다.** 재현성(`reliability.md`)은 "같은 사이트를 다시 재면
  같은 점수가 나오는가" 이고, 밴드는 "못 본 것 때문에 점수가 얼마나 흔들릴 수 있는가"
  다. 둘 다 작아야 리포트가 강하다.

### 4.2 Plane B 변경 직후

Plane B의 주요 변경(게이팅 항목 해제, 스키마 전면 도입 등) 배포 후 **8주 미만**이면
AVI는 아직 변경을 반영하지 않았을 가능성이 높다(`avr-model.md` §2-(2)).
이 경우 ARS-high · AVI-low 조합(Q2)을 **"반영 대기 중"** 으로 별도 표기하고,
Q2 처방(외부 권위 투자)을 즉시 개시하지 않도록 경고한다.

```
if plane_b_major_change_days_ago < 56 and quadrant == "Q2":
    → label 유지, prescription.headline 을 "반영 대기 — 재측정 후 확정" 으로 치환
```

### 4.3 시계열 단절

`comparison.series_break = true`인 구간에서는 사분면 **이동**을 성과로 보고하지 않는다.
모델 버전 변경으로 인한 AVI 변동과 실제 개선을 구분할 수 없기 때문이다.

## 5. 판정 의사코드

```python
AVI_THRESHOLD = 25.0
ARS_THRESHOLD = 60.0

QUADRANT = {
    (True,  True):  ("Q1", "리더"),
    (False, True):  ("Q2", "준비만 된 상태"),
    (True,  False): ("Q3", "브랜드 관성형"),
    (False, False): ("Q4", "미개척"),
}

def classify(avi, ars, avi_ci=None, coverage_ratio=1.0, free_tier=False):
    avi_high = avi >= AVI_THRESHOLD
    ars_high = ars >= ARS_THRESHOLD
    qid, label = QUADRANT[(avi_high, ars_high)]

    borderline = free_tier or coverage_ratio < 0.7
    if avi_ci is not None:
        borderline |= (avi_ci["lower"] < AVI_THRESHOLD <= avi_ci["upper"])

    return {
        "id": qid,
        "label": label,
        "avi_band": "high" if avi_high else "low",
        "ars_band": "high" if ars_high else "low",
        "avi_threshold": AVI_THRESHOLD,
        "ars_threshold": ARS_THRESHOLD,
        "borderline": borderline,
    }
```

**주의**: `ars`는 게이팅 적용 **후** 값을 쓴다(`plane_b.ars`, `raw_ars` 아님).
게이팅 발동 브랜드는 상한 40 < 60이므로 반드시 ARS-low로 분류된다 — 의도된 동작이다.

## 6. 임계값 변경 절차

임계값은 코드 상수가 아니라 **버전 관리 대상**이다.

1. 변경 제안에는 근거 데이터(코호트 표본 수, 분포)를 첨부한다.
2. 변경 시 `scoring.md`의 버전을 올리고 변경 사유를 이 문서에 남긴다.
3. 과거 리포트 소급 재판정 여부를 결정하고 명시한다. 기본값은 **소급하지 않음**이다
   (고객이 이미 받은 진단 결론이 사후에 바뀌는 것은 신뢰 문제다).
4. 임계값을 **고객별로 조정하지 않는다.** 조정 가능한 임계값은 원하는 사분면을 만들어낸다.
