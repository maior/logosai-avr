# AVR 모델 — AI Visibility & Readiness (총론)

버전: 1.0.0 · 상태: 명세 확정 (구현 전) · 근거: 내부 시장 분석 §6 (비공개)

---

## 1. 한 줄 정의

AVR은 브랜드의 AI 답변 노출을 **결과(Visibility)** 와 **원인(Readiness)** 두 평면으로 분리해 측정하고,
그 교차점에서 처방을 도출하는 진단 모델이다.

```
        ┌──────────────────────────────────────────────┐
        │ Plane A: VISIBILITY — 결과 · 블랙박스        │
        │ 실제 LLM/답변엔진 응답을 프로빙해 통계 추정  │
        │ 산출: AVI (0~100) + 신뢰구간                 │
        └──────────────────────────────────────────────┘
                          ↕  Gap Matrix
        ┌──────────────────────────────────────────────┐
        │ Plane B: READINESS — 원인 · 화이트박스       │
        │ 사이트·엔티티를 rubric으로 정적 감사         │
        │ 산출: ARS (0~100) + 항목별 근거              │
        └──────────────────────────────────────────────┘
```

---

## 2. 왜 두 평면을 분리하는가

시장의 모든 제품은 둘 중 하나만 한다. 그래서 둘 다 틀린 처방을 낸다.

| 제품 유형 | 하는 것 | 못 하는 것 | 결과적 오진 |
|---|---|---|---|
| AI 가시성 모니터링 SaaS (Otterly, Peec, Profound, GPTO) | Plane A만 | 왜 낮은지 설명 불가 | "점수가 낮네요" 이후가 없다 |
| 기술 SEO·AEO 감사 툴 | Plane B만 | 실제로 노출이 오르는지 모름 | 체크리스트를 다 채웠는데 안 뜨는 케이스를 설명 못 함 |

분리해야 하는 세 가지 구조적 이유:

**(1) 두 평면은 인과 방향이 다르다.**
Plane B는 자사가 직접 통제할 수 있는 변수(robots.txt, 스키마, 문서 구조)다.
Plane A는 통제 불가능한 변수(모델 파라미터, 학습 데이터, 제3자 언급)가 섞여 있다.
합쳐서 하나의 점수로 내면 **통제 가능한 부분과 불가능한 부분이 뒤섞여 액션이 나오지 않는다.**

**(2) 두 평면은 반응 시간이 다르다.**
Plane B 개선은 배포 즉시 반영된다. Plane A 변화는 재크롤링·인덱싱·모델 갱신을 거쳐
2주~3개월 뒤에 나타난다(GPTO 자사 발표 — 독립 검증되지 않음).
같은 시점에 같은 축으로 놓으면 **개선이 반영되기 전 시점의 낮은 AVI를 "실패"로 오독**한다.

**(3) 언급(mention)과 인용(citation)의 출처가 다르다.**
브랜드 언급은 모델 파라미터와 외부 신호에서 나오고, 자사 도메인 인용은 크롤링 가능한
자사 콘텐츠에서 나온다. Plane B를 고쳐도 언급은 안 늘고 인용만 느는 경우가 실재한다.
분리 측정해야 이 구분이 리포트에 남는다.

## 3. 두 평면의 산출물

| | Plane A | Plane B |
|---|---|---|
| 종합 지수 | **AVI** (AI Visibility Index) 0~100 | **ARS** (AEO Readiness Score) 0~100 |
| 구성 | 6채널 가중합 (`rubric/channels.yaml`) | 5 Pillar 가중합 (`rubric/pillars.yaml`) |
| 하위 지표 | MR, SoV, PosScore, CitShare, Sentiment SoV, FAI | 44개 항목 × 0/1/2 |
| 불확실성 | Wilson score interval (이항비율) | 미판정 항목 공시 (manual 11개) |
| 갱신 주기 | 주간(트래킹) + 월간(캘리브레이션) | 배포 시점 또는 월간 |
| 상세 명세 | `plane-a-visibility.md` | `plane-b-readiness.md` |

## 4. Gap Matrix — 진단의 결론 화면

두 평면을 각각 임계값으로 이분해 4사분면을 만든다. 임계값 규칙은 `scoring.md` 참조.

```
                    ARS 낮음 (< 60)        ARS 높음 (≥ 60)
                  ┌─────────────────────┬─────────────────────┐
   AVI 높음       │  Q3 브랜드 관성형   │  Q1 리더            │
   (≥ 25)         │  파워로 버티는 중   │  유지 · 확장        │
                  │  → 구조 부채 위험   │  → 방어 · 환각 관리 │
                  ├─────────────────────┼─────────────────────┤
   AVI 낮음       │  Q4 미개척          │  Q2 준비만 된 상태  │
   (< 25)         │  전면 착수          │  외부 신호가 병목   │
                  │  → 기초부터         │  → 사이트 그만 고쳐 │
                  └─────────────────────┴─────────────────────┘
```

### 4.1 사분면별 처방

#### Q1 — 리더 (AVI 높음 · ARS 높음)
**진단**: 구조도 갖췄고 실제로 노출된다. 문제는 유지와 정확성이다.
**처방**
- 우선순위 Pillar: **P5(신선도·운영) → P4(권위)**
- FAI(사실 정확도)를 1차 KPI로 전환한다. 노출이 이미 있는 브랜드는 **틀린 설명이 퍼지는 것**이 더 큰 리스크다.
- 경쟁사 SoV 방어: 비교형 질문에서 자사가 빠지기 시작하는 시점을 조기 경보로 잡는다.
- 하지 말 것: 새 스키마 추가, 새 랜딩 대량 생산. 한계효용이 거의 없다.

#### Q2 — 준비만 된 상태 (AVI 낮음 · ARS 높음)
**진단**: **가장 흔하고, 시장이 가장 못 짚는 사분면**이다. 사이트는 멀쩡한데 외부 인용·언급이 없어 안 뜬다.
경쟁사가 "사이트를 더 고치자"고 파는 전형적 오진 지점.
**처방**
- 우선순위 Pillar: **P4(권위) 단독**. P1~P3에 추가 투자하지 않는다.
- 핵심 항목: `P4-03`(권위 백링크), `P4-04`(무링크 언급), `P4-05`(제3자 카테고리 정의 일치), `P4-06`(언론 커버리지), `P4-09`(네이버 생태계 신뢰 신호)
- 전제 확인: ARS가 높은데 AVI가 낮은 원인이 **반영 지연**일 수도 있다. Plane B 주요 변경 배포 후 8주가 지나지 않았다면 Q2로 확정하지 말고 재측정한다.
- 두 번째 확인: 목표 질문 세트가 실제 사용자 질의가 아닐 가능성. 질문 설계 자체를 감사한다.

#### Q3 — 브랜드 관성형 (AVI 높음 · ARS 낮음)
**진단**: 브랜드 인지도·외부 언급 자산으로 버티는 중. 모델이 자사 사이트가 아닌 **제3자 서술**을 근거로 말하고 있다.
따라서 **답변 내용을 자사가 통제하지 못한다.**
**처방**
- 우선순위 Pillar: **P1(접근성) → P3(기계가독성) → P2(추출성)**
- 게이팅 발동(`P1-01`·`P1-03` 0점) 여부를 먼저 본다. 발동 중이라면 그것 하나가 전부다.
- CitShare와 MR의 격차를 본다. MR은 높은데 CitShare가 낮으면 "언급은 되지만 우리 페이지는 안 읽힌다"는 뜻이고, 이 상태에서 FAI가 낮으면 즉시 위험 신호다.
- 구조 부채는 브랜드 파워가 흔들리는 순간 한꺼번에 청구된다.

#### Q4 — 미개척 (AVI 낮음 · ARS 낮음)
**진단**: 기초가 없다. 순서대로 쌓는 것 외에 지름길이 없다.
**처방**
- 우선순위: **게이팅 해제 → P1 → P2 → P3 → P4 → P5** (엄격한 순차)
- 1단계(0~4주): `P1-01`, `P1-03` 게이팅 항목. 이게 0점이면 나머지 작업은 전부 매몰비용이다.
- 2단계(4~10주): P2 답변 우선 구조 + 정의문 통일(`P2-01`, `P2-08`) — 가장 저비용·고효과 구간
- 3단계(10주~): P3 스키마, 이후 P4
- 기대 관리: 첫 AVI 변화까지 최소 8~12주. 이 사분면에 "한 달 내 성과"를 약속하지 않는다.

### 4.2 경계 사례 처리

AVI 신뢰구간이 임계선을 걸치면(`gap_quadrant.borderline = true`) 사분면을 단정하지 않는다.
인접한 두 사분면의 처방을 병기하고, 표본 수를 늘린 재측정을 먼저 권고한다.
**단일 점추정으로 사분면을 확정해 처방을 파는 것이 이 시장의 기본 오류다.**

## 5. 인과 연결 — 로드맵 (v1 범위 밖)

Plane B 항목 변경 → Plane A 지표 변화를 패널 데이터로 축적해 회귀한다.

```
ΔAVI ~ ΔP1 + ΔP2 + ΔP3 + ΔP4 + ΔP5 + industry + brand_size + time_fe
```

목표: **"스키마를 붙이면 몇 점 오르나"에 숫자로 답한다.**
현재 업계 전체가 베스트프랙티스를 *믿음*으로 판매 중이다.

v1에서는 회귀를 수행하지 않는다. 대신 **회귀에 필요한 데이터 형식을 지금 확정한다** —
`report.schema.json`의 `comparison` 객체와 `item_result.score` 시계열이 그 입력이다.
표본이 30 브랜드 × 6회 측정에 도달하기 전 계수를 발표하지 않는다.

## 6. 파일 의존 관계

```
rubric/pillars.yaml   ──┐
                        ├─→ schema/report.schema.json ─→ 백엔드 스코어러 · 리포트 렌더러
rubric/channels.yaml  ──┘
```

`pillars.yaml`의 항목 id, `channels.yaml`의 채널 id는 `report.schema.json`의 enum과
**항상 일치해야 한다.** 항목 추가/삭제 시 세 파일을 같은 커밋에서 갱신한다.
