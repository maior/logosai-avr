# Plane A — Visibility 지표 명세

버전: 1.2.0 · 정본 채널 정의: `framework/rubric/channels.yaml`

## 0. 측정 단위 정의

| 용어 | 정의 |
|---|---|
| **question** | 고정된 목표 질문 하나. 질문 세트는 측정 주기 간 변경하지 않는다. |
| **response** | 한 번의 (question × channel × search_mode × repetition) 호출로 얻은 응답 하나 |
| **mention** | 응답 본문에 브랜드 엔티티가 등장한 사건 (도메인 링크 유무 무관) |
| **citation** | 응답이 출처로 제시한 URL의 도메인 |
| **n** | 해당 집계 단위의 총 응답 수. `n = questions × repetitions × |search_modes|` |

**주의**: mention과 citation은 다른 사건이다. 하나를 다른 하나로 대체하지 않는다.

## 1. 기본 지표

### 1.1 MR — Mention Rate

```
MR_c = m_c / n_c
```
- `m_c` = 채널 c의 응답 중 브랜드가 언급된 응답 수
- `n_c` = 채널 c의 총 응답 수
- 값역 [0, 1]. 이항비율이므로 반드시 §3의 신뢰구간과 함께 보고한다.

**엔티티 baseline 보정.** 브랜드명이 일반명사이거나 동명 엔티티가 존재하면 raw MR이 부풀려진다
(내부 분석 §5 Per-Entity Bias Mapping, 비공개). 브랜드와 무관한 대조 프롬프트 집합으로
false-positive rate `f`를 추정하고 차감한다.

```
MR_corrected = max(0, (MR_raw − f) / (1 − f))
```

보정을 적용한 경우 `mr`과 `mr_raw`를 **둘 다** 리포트에 남긴다 (스키마 강제).
`f`는 브랜드마다 다르므로 브랜드 간 raw MR 비교는 금지한다.

### 1.2 SoV — Share of Voice

```
SoV_c = (자사 언급 횟수) / (자사 + 지정 경쟁사 언급 횟수 합)
```
- 분모는 사전에 고정한 경쟁사 세트에 한정한다. "전체 브랜드"를 분모로 두면
  응답마다 등장하는 무관 브랜드 때문에 값이 불안정해진다.
- 경쟁사 세트를 바꾸면 시계열이 단절된다. 변경 시 `series_break = true`.

### 1.3 PosScore — 언급 순서 가중

응답 하나에서 브랜드가 `rank`번째로 언급되었을 때 (rank는 1부터):

```
pos(rank) = 1 / log2(1 + rank)
pos(미언급) = 0
```

| rank | 1 | 2 | 3 | 4 | 5 | 10 |
|---|---|---|---|---|---|---|
| pos | 1.000 | 0.631 | 0.500 | 0.431 | 0.387 | 0.289 |

채널 집계는 전체 응답에 대한 산술평균이다 (미언급 응답의 0도 포함):

```
PosScore_c = (1/n_c) · Σ_{i=1..n_c} pos(rank_i)
```

값역 [0, 1]. rank 1일 때만 1.0이므로 정규화가 불필요하다.
**MR과 PosScore를 동시에 보는 이유**: MR이 같아도 "항상 마지막에 곁다리로 언급"과
"항상 첫 번째로 추천"은 전혀 다른 상태다.

### 1.4 CitShare — 인용 점유

```
CitShare_c = (자사 도메인이 인용된 응답 수) / (인용을 하나라도 포함한 응답 수)
```
- 분모가 **총 응답 수가 아니다.** 검색 OFF 조건이나 인용을 제시하지 않는 응답은
  분모에서 제외한다. 그러지 않으면 검색 미사용 채널의 CitShare가 구조적으로 0이 된다.
- 인용을 포함한 응답이 하나도 없으면 `cit_share = null`, AVI 계산에서 해당 항을 제외하고
  `α, β`를 재정규화한다.
- 서브도메인·리다이렉트 목적지까지 자사 도메인으로 정규화한다.

### 1.5 Sentiment SoV

```
SentimentSoV_c = (자사 긍정 맥락 언급 수) / (자사 + 경쟁사 긍정 맥락 언급 수)
```
- 감성 라벨링은 LLM 판정기로 수행하되, **판정기 모델과 프롬프트를 리포트에 명시**한다.
- 3분류(positive / neutral / negative)를 사용하고, neutral은 분자·분모 모두에서 제외한다.
- 사람 라벨 100건과의 일치도(Cohen's κ)를 분기마다 재측정해 공시한다. κ < 0.6이면 지표를 보고하지 않는다.

### 1.6 FAI — Fact Accuracy Index

```
FAI = 1 − (오류 진술 수 / 총 검증 진술 수)
```
- 브랜드에 대한 AI의 서술을 진술 단위로 분해하고, 사실 대장(fact sheet)과 대조한다.
- 사실 대장은 고객이 서명한 확정 문서여야 한다. 이것 없이 FAI를 계산하지 않는다.
- 표본 수(`fai_sample_size`)를 반드시 병기한다. 소표본 FAI는 오해를 부른다.
- **Q1(리더) 사분면의 1차 KPI.** 노출이 이미 있는 브랜드는 틀린 설명의 확산이 더 큰 리스크다.

## 2. 종합 지수 AVI

```
AVI = 100 × Σ_c  w_c · ( α·MR_c + β·PosScore_c + γ·CitShare_c )

  c ∈ 측정된 채널
  w_c : channels.yaml 의 weight (미측정 채널 제외 후 Σ w_c = 1 로 재정규화)
  α = 0.5,  β = 0.3,  γ = 0.2   (α + β + γ = 1)
```

### 2.1 계수 α=0.5 / β=0.3 / γ=0.2 의 근거

세 계수는 **관측 가능성 × 사업적 의미 × 통제 가능성** 세 축의 절충이다.

| 계수 | 값 | 근거 |
|---|---|---|
| **α (MR)** | 0.5 | 셋 중 유일하게 전 채널에서 동일 정의로 관측되고, 표본 오차를 정확히 계량할 수 있는 이항 사건이다. 노출의 **필요조건**이기도 하다 — 언급이 없으면 순서도 인용도 성립하지 않는다. 따라서 단일 최대 가중. |
| **β (PosScore)** | 0.3 | 사용자 클릭·인지는 첫 언급에 강하게 편중되므로 순서는 MR 다음으로 중요하다. 다만 순서 파싱은 응답 형식(리스트 vs 산문)에 따라 추출 신뢰도가 달라져 MR보다 잡음이 크다. 그래서 MR보다 낮게 둔다. |
| **γ (CitShare)** | 0.2 | 자사가 가장 직접 통제할 수 있는 지표(= Plane B와 인과가 가장 짧은 지표)라 진단 가치가 크다. 그러나 검색 OFF 조건과 인용 미제시 채널에서는 **정의상 관측 불가**라 결측이 잦다. 결측이 잦은 항에 큰 가중을 주면 채널 간 비교가 왜곡되므로 최소 가중. |

이 값들은 **v1 고정값이며 이론적 최적해가 아니다.** 근거는 위 세 축의 정성적 판단이고,
`avr-model.md` §5의 패널 회귀에서 ΔAVI와 사업 성과의 상관이 확보되면 재추정한다.
그 전까지 계수를 브랜드별로 조정하는 것을 금지한다 — 조정 가능한 계수는 원하는 결론을 만들어낸다.

### 2.2 결측 처리

- 채널이 미측정(`measured = false`)이면 그 채널을 빼고 `w_c`를 재정규화하며,
  `plane_a.weight_renormalized = true`로 표시한다.
- `CitShare_c`가 null이면 해당 채널에서만 `α' = α/(α+β) = 0.625`, `β' = β/(α+β) = 0.375`로
  재정규화해 두 항으로 계산한다.
- **Google AI Overviews 미노출은 0점이 아니라 미측정이다.** 노출 자체가 질의·지역·계정에 따라
  불안정하므로 0으로 처리하면 AVI가 체계적으로 하향 편향된다.

## 3. 통계적 신뢰구간 — Wilson score interval

### 3.1 왜 Wilson인가

MR은 이항비율이다. 정규근사(Wald) 구간은 `p̂`가 0이나 1에 가깝거나 n이 작을 때
구간이 [0,1]을 벗어나거나 폭이 0으로 붕괴한다. MR은 실제로 0에 가까운 경우가 흔하다
(신규 브랜드의 초기 베이스라인). **Wilson score interval은 이 영역에서 실제 피복확률이
명목 수준에 훨씬 가깝다.** 따라서 정본으로 채택한다.

### 3.2 공식

`x` = 언급 응답 수, `n` = 총 응답 수, `p̂ = x/n`, `z = z_{1−α/2}` (95% 신뢰수준에서 `z = 1.959964`)

```
              p̂ + z²/(2n)  ±  z · sqrt( p̂(1−p̂)/n  +  z²/(4n²) )
CI(p) =      ──────────────────────────────────────────────────────
                              1 + z²/n
```

중심(center)과 반폭(half-width)으로 분리해 쓰면:

```
center     = ( p̂ + z²/(2n) ) / ( 1 + z²/n )
half_width = ( z · sqrt( p̂(1−p̂)/n + z²/(4n²) ) ) / ( 1 + z²/n )

lower = max(0, center − half_width)
upper = min(1, center + half_width)
```

참조 구현:

```python
from math import sqrt

def wilson(x: int, n: int, z: float = 1.959964) -> tuple[float, float]:
    if n == 0:
        raise ValueError("n must be > 0")
    p = x / n
    denom = 1 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = (z * sqrt(p * (1 - p) / n + z * z / (4 * n * n))) / denom
    return (max(0.0, center - half), min(1.0, center + half))
```

### 3.3 필요 표본수 n

목표: 95% CI의 반폭 `E`를 만족하는 최소 n. 가장 보수적인 `p̂ = 0.5`(분산 최대) 기준으로
정규근사 표본수 공식을 쓴다.

```
n ≳ z² / (4 · E²)
```

| 목표 반폭 E | 필요 n (p̂=0.5 기준) |
|---|---|
| ±10.0%p | 97 |
| ±7.0%p | 196 |
| ±5.0%p | **385** |
| ±3.0%p | 1,068 |
| ±2.0%p | 2,401 |

계산: `E = 0.05` → `n ≳ 1.959964² / (4 × 0.05²) = 3.8415 / 0.01 = 384.2` → **385**.

`p̂`가 0.5에서 멀면 실제 필요 n은 더 작다 (`n ≳ z²·p̂(1−p̂)/E²`).
예: `p̂ ≈ 0.2`, `E = 0.05` → `n ≳ 246`.
운영 기준은 **채널당 n ≥ 385** 를 목표로 하되, 예산 제약 시 채널별 예상 `p̂`로 개별 산정하고
그 사실과 실제 n을 리포트에 명시한다.

**n의 구성**: `n = questions × repetitions × |search_modes|`.
예) 질문 100개 × 반복 2회 × (검색 ON/OFF) = 400.
`supports_search_toggle: false`인 채널(Perplexity, 네이버, AI Overviews)은 `|search_modes| = 1`이므로
같은 n을 채우려면 질문 수나 반복 수를 늘려야 한다.

### 3.4 클러스터 보정 — 관측은 독립이 아니다 (강제)

프로빙 설계는 **질문 M개 × 채널 C개 × 반복 k회**다. 같은 질문에 대한 여러 응답은
서로 독립이 아니다. 브랜드가 그 질문에 강하면 그 질문의 응답이 통째로 언급되고,
약하면 통째로 빠진다. 그런데 Wilson 구간의 `n` 은 **독립 관측 수**를 뜻한다.
raw `n` 을 그대로 넣으면 없는 정보를 있다고 주장하는 것이 된다.

Kish 설계효과로 보정한다.

```
DEFF   = 1 + (k − 1)·ρ            k = 클러스터 크기(질문당 관측 수), ρ = 급내상관
n_eff  = n / DEFF
```

**점추정 p̂ 은 건드리지 않는다.** 보정은 분모에만 건다 — 중심이 움직이면 그건
보정이 아니라 값의 왜곡이다. Wilson 구간은 `p̂` 를 유지한 채 `n_eff` 로 폭만 넓힌다.

| 항목 | 값 |
|---|---|
| 원표본 | 질문 100 × 반복 4 = `n = 400` |
| ρ = 0.5, k = 4 | `DEFF = 2.5`, `n_eff = 160` |
| 순진한 구간 (raw n) | MR 33% → [28.57%, 37.75%], 반폭 ±4.59%p |
| 보정 구간 (n_eff) | MR 33% → [26.19%, 40.61%], 반폭 ±7.21%p |

보정을 빠뜨린 구간은 참값의 **63.6% 폭**이다. 이것이 구간 없는 점추정보다 나쁜 이유는,
구간을 붙였다는 사실 자체가 **없는 정밀도를 보증하기** 때문이다. 독자는 검증했다고
믿게 되고, 그 믿음의 근거는 틀려 있다.

ρ 는 관측에서 추정한다(질문을 클러스터로 본 ANOVA 방식). 추정할 수 없으면 보정을
생략하는 것이 아니라 **그 사실을 공시**한다.

#### 3.4.1 보고 형식 (강제)

```
❌ 금지:  "MR 33%"
❌ 금지:  "MR 33.0% (95% CI 28.5%–37.8%, n=400)"      ← 보정 없는 구간
✅ 정본:  "MR 33.0% (95% CI 26.2%–40.6%, n=400, n_eff=160, ρ=0.50, Wilson)"
```

업계 전체가 점추정만 표기한다. 구간을 붙이는 순간 신뢰도의 격이 달라지고,
동시에 **"n=40으로 잰 33%"를 팔 수 없게 된다.** 그게 이 규칙의 요점이다.

그리고 `n_eff` 와 `ρ` 를 함께 적지 않으면, **구간을 붙였다는 사실이 오히려 검증을
막는다.** 독자가 분모를 다시 계산할 수 없기 때문이다. 세 값은 함께 나가거나 함께
빠진다 — 하나만 빼는 선택지는 없다.

## 4. 개선 유의성 검정 — two-proportion z-test

"MR이 35.4% → 40.6%로 올랐다"는 주장은 검정 없이는 의미가 없다.
반드시 **Matched Cohort**(동일 질문 세트 × 동일 채널 × 동일 검색 모드) 위에서만 비교한다.

### 4.1 공식

기준 시점 `(x₁, n₁)`, 비교 시점 `(x₂, n₂)`, `p̂₁ = x₁/n₁`, `p̂₂ = x₂/n₂`

```
             x₁ + x₂
p̂_pool  =  ───────────
             n₁ + n₂

                    p̂₂ − p̂₁
z  =  ─────────────────────────────────────────
       sqrt( p̂_pool (1 − p̂_pool) (1/n₁ + 1/n₂) )

p_value = 2 · (1 − Φ(|z|))        (양측 검정)
```

`α = 0.05`에서 `|z| > 1.96` 이면 유의. 결과는 `comparison.mr_significance[]`에 기록한다.

```python
from math import sqrt, erf

def two_proportion_z(x1: int, n1: int, x2: int, n2: int) -> tuple[float, float]:
    p1, p2 = x1 / n1, x2 / n2
    pool = (x1 + x2) / (n1 + n2)
    se = sqrt(pool * (1 - pool) * (1 / n1 + 1 / n2))
    if se == 0:
        return (0.0, 1.0)
    z = (p2 - p1) / se
    p_value = 2 * (1 - 0.5 * (1 + erf(abs(z) / sqrt(2))))
    return (z, p_value)
```

### 4.2 검정도 n_eff 위에서 한다 (강제)

§3.4 는 구간에만 적용되는 규칙이 아니다. `two_proportion_z` 의 `n₁`·`n₂` 에도 **보정된
분모**를 넣는다. 넣지 않으면 잡음이 성과로 판정된다.

```
k_eff = round(p̂ · n_eff)          점추정을 유지한 채
n_eff = n / DEFF                   분모만 줄인다
z, p  = two_proportion_z(k_eff₁, n_eff₁, k_eff₂, n_eff₂)
```

**실제 사례** (골든 케이스 `stat-two-proportion-clustered-flips-significance`).
한 업체가 매칭쌍 3,141개에서 `35.4% → 40.6%` 개선을 공개했다.

| 처리 | n_eff | p | 판정 |
|---|---|---|---|
| 보정 없음 | 3,141 | 2.3e-05 | 유의 |
| k=5, ρ=0.3 | 1,428 | 0.0038 | 유의 |
| k=5, ρ=0.5 | 1,047 | 0.015 | 유의 |
| **k=12, ρ=0.5** | **483** | **0.097** | **유의하지 않음** |

여기서 얻을 결론은 "그 주장이 거짓이다" 가 **아니다.** 대부분의 그럴듯한 가정에서
그 개선은 유의하다. 결론은 이것이다 — **ρ 를 공시하지 않으면 발표자도 독자도
유의한지 알 수 없다.** 12는 그 업체 자신이 밝힌 채널 수다.

그래서 개선 주장에는 `n`·`n_eff`·`ρ` 가 함께 실려야 한다. 셋 중 하나라도 없는 주장은
반박 대상이 아니라 **검정 불가**이며, 리포트는 그렇게 적는다.

> **짝지음 설계 주의.** Matched Cohort 는 짝지음(paired) 설계이므로 정확한 검정은
> McNemar 다. 비짝지음 z 는 짝지음 데이터에서 검정력을 잃으므로, 짝지음 데이터에
> 비짝지음 z 를 적용한 결과는 **상한 판정**으로만 읽는다. 원자료에 짝 정보가 있으면
> McNemar 를 쓰고, 어느 쪽을 썼는지 리포트에 명시한다.

### 4.3 운영 규칙

1. **유의하지 않으면 "개선"이라고 쓰지 않는다.** `significant = false`이면 리포트 문구는
   "변화가 관측되었으나 통계적으로 유의하지 않음 (p = 0.18)"이다.
2. 다중 비교 보정: 6채널을 동시에 검정하면 우연히 하나가 유의할 확률이 커진다.
   채널별 결론을 낼 때는 Holm–Bonferroni 보정을 적용하고, 보정 적용 여부를 명시한다.
3. 모델 버전이 조용히 바뀌면 시계열이 단절된다(내부 분석 §8, 비공개).
   `series_break = true`인 구간을 가로지르는 개선 주장은 금지한다.

## 5. 프록시 격차 δ — 저가 트래킹 모델의 대가

### 5.1 문제

주간 트래킹을 플래그십 모델로 돌리면 원가가 감당되지 않는다
(채널당 n≈385 × 6채널 × 주간). 그래서 `channels.yaml`은 채널마다
`tracking_model`(주간·저가)과 `calibration_model`(월간·플래그십)을 분리한다.

**하지만 저가 모델과 플래그십 모델의 MR은 같지 않다.** 다른 모델이므로 당연하다.
이 차이를 숨기고 트래킹 수치를 "ChatGPT의 MR"이라고 파는 것은 부정확한 보고다.

### 5.1-1 δ 는 재는 것보다 **없애는 것**이 낫다 (v1.1.0)

`calibration_model` 은 "가장 비싼 모델"이 아니라 **그 채널에서 소비자가 실제로 받는
모델**이다. 그 둘을 혼동하면 아무도 경험하지 않는 격차를 비싸게 재게 된다.

그러면 당연한 귀결이 하나 나온다 — **소비자 모델이 충분히 싸면 그것으로 직접
트래킹하고, δ 를 아예 만들지 않는다.** 프록시 격차는 정의상 0 이 되고, 캘리브레이션
회차·저장·공시가 통째로 불필요해진다. 근사보다 관측이 낫다.

실제 적용(channels v1.2.0): `gemini` 채널은 소비자가 받는 `gemini-3.8-flash` 로 직접
트래킹하고 `calibration_model: null` 이다. 트래킹 모델을 **더 비싼 것으로 올렸는데도**
그 채널 월 원가가 68% 줄었다 — 캘리브레이션이 사라지기 때문이다.

**채널을 건너뛴 캘리브레이션은 금지한다.** 채널은 측정 도구가 아니라 **소비자가 쓰는
창구**이고, `channels.yaml` 의 가중치는 그 창구의 국내 이용 점유율이다. A 채널을 B
공급자의 모델로 캘리브레이션하면 나오는 값은 δ 가 아니라 **두 채널의 차이**이며,
우리는 이미 그 둘을 각자의 가중치로 따로 재고 있으므로 같은 관측이 이중 계상된다.

### 5.2 정의

동일 질문 세트·동일 검색 모드에서 같은 기간에 두 모델을 호출해:

```
δ_c = MR_c(tracking_model) − MR_c(calibration_model)
```

- 부호를 유지한다. `δ > 0`이면 저가 모델이 브랜드를 과다 언급하고 있다는 뜻이다.
- 캘리브레이션 표본은 트래킹보다 작아도 되지만 `n ≥ 100`을 하한으로 한다.
- `δ`의 유의성은 §4의 two-proportion z-test로 검정한다.

### 5.2-1 δ 는 채널 상수가 아니다 — 첫 실측 (v1.2.0)

2026-09-22, `claude` 채널(`haiku-4-5` 대 `sonnet-5`)을 처음 쟀다. 두 사이트에서
**부호가 반대로** 나왔다.

| 대상 | 트래킹 (haiku) | 캘리브레이션 (sonnet-5) | δ | 검정 |
|---|---|---|---|---|
| A (질문 2개) | 3/4 = 75% | 0/4 = 0% | **+75.0%p** [8.5, 95.4] | p = 0.029 |
| B (질문 6개) | 2/12 = 17% | 6/12 = 50% | **−33.3%p** [−60.7, 4.1] | p = 0.083 (유의하지 않음) |

같은 채널, 같은 모델 쌍, 같은 날이다. 다른 것은 **질문 세트**뿐이다.

따라서 **δ 를 "이 채널의 보정 상수" 로 쓰지 않는다.** 저가 모델이 플래그십보다
브랜드를 더 많이 부를 수도, 덜 부를 수도 있고, 그 방향이 질문에 따라 뒤집힌다.
채널 하나에 δ 값 하나를 붙여 전사적으로 적용하는 구현은 **어떤 사이트에서는
보정이 편향을 키운다.**

규칙 셋이 여기서 나온다.

1. **δ 는 사이트 단위로만 쓴다.** 남의 사이트에서 잰 δ 를 끌어다 붙이면 그건
   관측이 아니다. 참조 구현은 `site_id` 로 범위를 좁히고 채널별 최신 것 하나만 쓴다.
2. **δ 로 MR 을 보정하지 않는다.** 공시만 한다. 보정은 δ 가 안정적이라는 가정을
   요구하는데, 위 표가 그 가정을 반증한다.
3. **표본 하한을 공시에 싣는다.** 위 둘은 각각 n=4 · n=12 로 권장 하한(n≥100)에
   한참 못 미친다. 구현은 하한 미달을 **경고로 표시**해야 하며, 숨기고 값만 내면
   독자가 ±75%p 짜리 추정을 확정된 보정치로 읽는다.

> **이 절은 "δ 를 없애는 것이 낫다"(§5.1-1)의 근거를 강화한다.** 재기 어렵고,
> 재도 불안정하고, 써먹으려면 안정성 가정이 필요한 값이다. 소비자 모델로 직접
> 트래킹할 수 있으면 그렇게 한다 — `gemini` 가 그 경로다.

### 5.3 공시 의무 (강제)

1. 모든 리포트의 `plane_a.proxy_gap[]`에 채널별 `δ`, 두 모델 id, 캘리브레이션 n, 측정일,
   유의 여부를 기록한다. **`calibration_model` 이 선언된 API 보유 채널은 필수.**
   `calibration_model: null`(§5.1-1, 트래킹 = 소비자 모델)인 채널은 δ 산출 대상이
   아니며, 그 사실을 **"트래킹 모델이 소비자 모델과 동일 — 프록시 격차 없음"** 으로
   공시한다. 침묵하지 않는다. 격차가 없다는 것도 관측이다.
2. `api_available: false`인 채널(naver_ai_briefing, google_ai_overviews)은 모델 선택 개념이
   없으므로 δ 산출 대상에서 제외하고, 대신 **수집 방식(스크래핑/수동 캡처)을
   `limitations`에 명시**한다.
3. `|δ| > 0.05` 이고 유의하면 리포트 본문에 경고를 노출한다:
   > "본 채널의 주간 수치는 `gpt-5.6-luna` 기준이며, `gpt-5.6-terra` 대비 +6.2%p 과다
   > 추정됩니다(n=120, p=0.01). 절대 수준 해석 시 이 격차를 감안하십시오."

   모델 이름은 예시가 아니라 **정본(`rubric/channels.yaml`)에서 읽는다.** 여기에 특정
   모델을 박아 두면 채널 정본이 바뀔 때 명세만 옛 이름을 말하게 된다 -- 실제로
   channels 1.0.0 → 1.1.0 에서 그런 상태가 됐다.

   **δ 를 아직 재지 않았다면 그 사실을 공시한다.** 침묵하면 독자는 이 수치가 소비자가
   쓰는 플래그십 기준이라고 읽는다. 아니고 저가 트래킹 모델 기준이며, 그 차이를 우리는
   모른다. 문구 생성처는 한 곳이어야 한다(참조 구현: `calibration/disclosure.py`).
4. `δ`는 **시계열 비교에서는 상쇄된다** (같은 트래킹 모델끼리 비교하므로).
   따라서 δ가 커도 "개선 추세" 판정은 유효하다. 무효가 되는 것은 **절대 수준 주장**뿐이다.
   이 구분을 리포트에 명시한다.
5. 캘리브레이션 주기: 월 1회. 모델 제공자가 버전을 갱신하면 즉시 재측정한다.

## 6. 질문 세트 구성 — 측정 도구를 만드는 절차 (2026-09-17)

### 6.1 질문 세트는 파라미터가 아니라 **측정 도구**다

§0 은 질문을 "고정된 목표 질문 하나. 질문 세트는 측정 주기 간 변경하지 않는다" 로
정의했다. **안정성만 말하고 구성은 말하지 않았다.** 그 공백이 실제로 측정을 막았다.

MR·SoV·CitShare 는 전부 "이 질문들에 대해" 의 값이다. 질문을 바꾸면 같은 사이트의
같은 날 값이 달라진다. **누가 어떤 질문을 골랐는가가 결과를 정한다.** 그래서 질문
작성은 설정이 아니라 측정 설계이고, 절차가 없으면 숫자에 근거가 없다.

### 6.2 구성 규칙

**① 질문에 브랜드 이름을 넣지 않는다.**
`"GPTO 는 뭐하는 회사야?"` 는 아무것도 재지 않는다 — 당연히 언급된다. 우리가 재는
것은 **그 브랜드를 모르는 사람의 질문에 그 브랜드가 떠오르는가**다. 별칭
(`brand_aliases`)도 마찬가지다.

**② 카테고리에서 나온다. 브랜드에서 나오지 않는다.**
판정: **같은 카테고리의 경쟁사에 그대로 써도 말이 되는가.** 안 되면 그 질문은 이
브랜드에 맞춰 재단된 것이다.

**③ 사이트 콘텐츠를 보고 쓰지 않는다.**
그 사이트가 답하는 질문을 골라 물으면 인용률이 구조적으로 올라간다. **순환이다.**
질문은 카테고리 정의에서 쓰고, 사이트를 읽는 것은 그 뒤다. 순서를 기록한다.

**④ 경쟁사도 답이 될 수 있어야 한다.**
한 회사만이 답일 수 있는 질문은 판별하지 않는다. `competitors` 에 적은 이름들이
그 질문의 후보로 자연스러운지 확인한다.

**⑤ 동음이의어를 배제한다.**
`off_topic_terms` 로 다른 뜻의 등장을 거른다 (예: AEO 는 "Authorized Economic
Operator" 이기도 하다). 이걸 빠뜨리면 언급률이 위로 편향된다.

### 6.3 추적용 세트와 코호트 비교용 세트는 **다른 물건**이다

| | 추적 (tracking) | 코호트 비교 (cohort) |
|---|---|---|
| 목적 | 한 브랜드의 **시계열** | 브랜드 **사이의** 비교 |
| 세트 | 브랜드마다 다름 | 같은 카테고리 안에서 **공유** |
| 바꾸면 | 그 브랜드의 과거 비교가 깨진다 | 코호트 전체가 깨진다 |

**섞으면 시계열도 횡단면도 아닌 것이 된다.** 브랜드마다 다른 질문으로 인용률을
비교하면, 쉬운 질문을 받은 브랜드가 높게 나온다. 그 순위는 브랜드가 아니라 질문의
순위다.

세트를 바꾸면 그 이전 측정과 비교할 수 없다. §4 의 Matched Cohort 규칙과 같다 —
동일 질문 세트가 아니면 개선 검정 자체가 성립하지 않는다.

### 6.4 코호트 비교의 전제 — 같은 카테고리

인용률의 기저는 카테고리마다 다르다. 어떤 분야는 AI 가 출처를 자주 달고 어떤 분야는
거의 안 단다. 카테고리가 섞인 코호트에서 인용률을 비교하면 **카테고리 효과가 사이트
준비도 효과로 읽힌다.**

> **실측 (2026-09-17).** `REMEASURE_28.md` 의 국내 28곳은 전부 다른 카테고리였다 —
> 여행·중고패션·수학교육·세탁·데이팅·APM·배양육·언론 …. 3곳 이상인 카테고리는
> **AEO 대행 하나뿐**이었고, 그 셋은 ARS 66.0·63.7·50.6 으로 **전부 상위권**이라
> 예측변수의 분산도 없었다.
>
> 즉 **그 코호트로는 임계값을 검증할 수 없다.** 돈을 쓰기 전에 알아야 하는 사실이고,
> 이 절이 없었다면 쓴 뒤에 알았을 것이다.

임계값 검증(`scoring.md` §2)을 목적으로 코호트를 구성한다면 조건은 셋이다.

1. **같은 카테고리** 안에서 고른다
2. 그 안에서 **ARS 가 넓게 퍼져 있다** (전원 고득점이면 판별을 못 잰다)
3. 브랜드 수가 판별 통계의 검정력을 만족한다 (`required_sample_size` 로 계산)

### 6.5 기록 의무

질문 세트마다 다음을 남긴다. **이것이 없으면 그 세트로 잰 값은 재현할 수 없다.**

- 작성자와 작성일
- 무엇을 보고 썼는가 (카테고리 정의 · 검색어 데이터 · 고객 인터뷰 …)
- **사이트를 읽기 전에 썼는가** (§6.2-③)
- 이 세트를 공유하는 브랜드 목록 (코호트용이면)
