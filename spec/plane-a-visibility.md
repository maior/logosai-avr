# Plane A — Visibility 지표 명세

버전: 1.0.0 · 정본 채널 정의: `framework/rubric/channels.yaml`

## 0. 측정 단위 정의

| 용어 | 정의 |
|---|---|
| **question** | 고정된 목표 질문 하나. 질문 세트는 측정 주기 간 변경하지 않는다. |
| **response** | 한 번의 (question × channel × search_mode × repetition) 호출로 얻은 응답 하나 |
| **mention** | 응답 본문에 브랜드 엔티티가 등장한 사건 (도메인 링크 유무 무관) |
| **citation** | 응답이 출처로 제시한 URL의 도메인 |
| **n** | 해당 집계 단위의 총 응답 수. `n = questions × repetitions × |search_modes|` |

**주의**: mention과 citation은 다른 사건이다. 하나를 다른 하나로 대체하지 않는다.

## 1. 기본 지표

### 1.1 MR — Mention Rate

```
MR_c = m_c / n_c
```
- `m_c` = 채널 c의 응답 중 브랜드가 언급된 응답 수
- `n_c` = 채널 c의 총 응답 수
- 값역 [0, 1]. 이항비율이므로 반드시 §3의 신뢰구간과 함께 보고한다.

**엔티티 baseline 보정.** 브랜드명이 일반명사이거나 동명 엔티티가 존재하면 raw MR이 부풀려진다
(내부 분석 §5 Per-Entity Bias Mapping, 비공개). 브랜드와 무관한 대조 프롬프트 집합으로
false-positive rate `f`를 추정하고 차감한다.

```
MR_corrected = max(0, (MR_raw − f) / (1 − f))
```

보정을 적용한 경우 `mr`과 `mr_raw`를 **둘 다** 리포트에 남긴다 (스키마 강제).
`f`는 브랜드마다 다르므로 브랜드 간 raw MR 비교는 금지한다.

### 1.2 SoV — Share of Voice

```
SoV_c = (자사 언급 횟수) / (자사 + 지정 경쟁사 언급 횟수 합)
```
- 분모는 사전에 고정한 경쟁사 세트에 한정한다. "전체 브랜드"를 분모로 두면
  응답마다 등장하는 무관 브랜드 때문에 값이 불안정해진다.
- 경쟁사 세트를 바꾸면 시계열이 단절된다. 변경 시 `series_break = true`.

### 1.3 PosScore — 언급 순서 가중

응답 하나에서 브랜드가 `rank`번째로 언급되었을 때 (rank는 1부터):

```
pos(rank) = 1 / log2(1 + rank)
pos(미언급) = 0
```

| rank | 1 | 2 | 3 | 4 | 5 | 10 |
|---|---|---|---|---|---|---|
| pos | 1.000 | 0.631 | 0.500 | 0.431 | 0.387 | 0.289 |

채널 집계는 전체 응답에 대한 산술평균이다 (미언급 응답의 0도 포함):

```
PosScore_c = (1/n_c) · Σ_{i=1..n_c} pos(rank_i)
```

값역 [0, 1]. rank 1일 때만 1.0이므로 정규화가 불필요하다.
**MR과 PosScore를 동시에 보는 이유**: MR이 같아도 "항상 마지막에 곁다리로 언급"과
"항상 첫 번째로 추천"은 전혀 다른 상태다.

### 1.4 CitShare — 인용 점유

```
CitShare_c = (자사 도메인이 인용된 응답 수) / (인용을 하나라도 포함한 응답 수)
```
- 분모가 **총 응답 수가 아니다.** 검색 OFF 조건이나 인용을 제시하지 않는 응답은
  분모에서 제외한다. 그러지 않으면 검색 미사용 채널의 CitShare가 구조적으로 0이 된다.
- 인용을 포함한 응답이 하나도 없으면 `cit_share = null`, AVI 계산에서 해당 항을 제외하고
  `α, β`를 재정규화한다.
- 서브도메인·리다이렉트 목적지까지 자사 도메인으로 정규화한다.

### 1.5 Sentiment SoV

```
SentimentSoV_c = (자사 긍정 맥락 언급 수) / (자사 + 경쟁사 긍정 맥락 언급 수)
```
- 감성 라벨링은 LLM 판정기로 수행하되, **판정기 모델과 프롬프트를 리포트에 명시**한다.
- 3분류(positive / neutral / negative)를 사용하고, neutral은 분자·분모 모두에서 제외한다.
- 사람 라벨 100건과의 일치도(Cohen's κ)를 분기마다 재측정해 공시한다. κ < 0.6이면 지표를 보고하지 않는다.

### 1.6 FAI — Fact Accuracy Index

```
FAI = 1 − (오류 진술 수 / 총 검증 진술 수)
```
- 브랜드에 대한 AI의 서술을 진술 단위로 분해하고, 사실 대장(fact sheet)과 대조한다.
- 사실 대장은 고객이 서명한 확정 문서여야 한다. 이것 없이 FAI를 계산하지 않는다.
- 표본 수(`fai_sample_size`)를 반드시 병기한다. 소표본 FAI는 오해를 부른다.
- **Q1(리더) 사분면의 1차 KPI.** 노출이 이미 있는 브랜드는 틀린 설명의 확산이 더 큰 리스크다.

## 2. 종합 지수 AVI

```
AVI = 100 × Σ_c  w_c · ( α·MR_c + β·PosScore_c + γ·CitShare_c )

  c ∈ 측정된 채널
  w_c : channels.yaml 의 weight (미측정 채널 제외 후 Σ w_c = 1 로 재정규화)
  α = 0.5,  β = 0.3,  γ = 0.2   (α + β + γ = 1)
```

### 2.1 계수 α=0.5 / β=0.3 / γ=0.2 의 근거

세 계수는 **관측 가능성 × 사업적 의미 × 통제 가능성** 세 축의 절충이다.

| 계수 | 값 | 근거 |
|---|---|---|
| **α (MR)** | 0.5 | 셋 중 유일하게 전 채널에서 동일 정의로 관측되고, 표본 오차를 정확히 계량할 수 있는 이항 사건이다. 노출의 **필요조건**이기도 하다 — 언급이 없으면 순서도 인용도 성립하지 않는다. 따라서 단일 최대 가중. |
| **β (PosScore)** | 0.3 | 사용자 클릭·인지는 첫 언급에 강하게 편중되므로 순서는 MR 다음으로 중요하다. 다만 순서 파싱은 응답 형식(리스트 vs 산문)에 따라 추출 신뢰도가 달라져 MR보다 잡음이 크다. 그래서 MR보다 낮게 둔다. |
| **γ (CitShare)** | 0.2 | 자사가 가장 직접 통제할 수 있는 지표(= Plane B와 인과가 가장 짧은 지표)라 진단 가치가 크다. 그러나 검색 OFF 조건과 인용 미제시 채널에서는 **정의상 관측 불가**라 결측이 잦다. 결측이 잦은 항에 큰 가중을 주면 채널 간 비교가 왜곡되므로 최소 가중. |

이 값들은 **v1 고정값이며 이론적 최적해가 아니다.** 근거는 위 세 축의 정성적 판단이고,
`avr-model.md` §5의 패널 회귀에서 ΔAVI와 사업 성과의 상관이 확보되면 재추정한다.
그 전까지 계수를 브랜드별로 조정하는 것을 금지한다 — 조정 가능한 계수는 원하는 결론을 만들어낸다.

### 2.2 결측 처리

- 채널이 미측정(`measured = false`)이면 그 채널을 빼고 `w_c`를 재정규화하며,
  `plane_a.weight_renormalized = true`로 표시한다.
- `CitShare_c`가 null이면 해당 채널에서만 `α' = α/(α+β) = 0.625`, `β' = β/(α+β) = 0.375`로
  재정규화해 두 항으로 계산한다.
- **Google AI Overviews 미노출은 0점이 아니라 미측정이다.** 노출 자체가 질의·지역·계정에 따라
  불안정하므로 0으로 처리하면 AVI가 체계적으로 하향 편향된다.

## 3. 통계적 신뢰구간 — Wilson score interval

### 3.1 왜 Wilson인가

MR은 이항비율이다. 정규근사(Wald) 구간은 `p̂`가 0이나 1에 가깝거나 n이 작을 때
구간이 [0,1]을 벗어나거나 폭이 0으로 붕괴한다. MR은 실제로 0에 가까운 경우가 흔하다
(신규 브랜드의 초기 베이스라인). **Wilson score interval은 이 영역에서 실제 피복확률이
명목 수준에 훨씬 가깝다.** 따라서 정본으로 채택한다.

### 3.2 공식

`x` = 언급 응답 수, `n` = 총 응답 수, `p̂ = x/n`, `z = z_{1−α/2}` (95% 신뢰수준에서 `z = 1.959964`)

```
              p̂ + z²/(2n)  ±  z · sqrt( p̂(1−p̂)/n  +  z²/(4n²) )
CI(p) =      ──────────────────────────────────────────────────────
                              1 + z²/n
```

중심(center)과 반폭(half-width)으로 분리해 쓰면:

```
center     = ( p̂ + z²/(2n) ) / ( 1 + z²/n )
half_width = ( z · sqrt( p̂(1−p̂)/n + z²/(4n²) ) ) / ( 1 + z²/n )

lower = max(0, center − half_width)
upper = min(1, center + half_width)
```

참조 구현:

```python
from math import sqrt

def wilson(x: int, n: int, z: float = 1.959964) -> tuple[float, float]:
    if n == 0:
        raise ValueError("n must be > 0")
    p = x / n
    denom = 1 + z * z / n
    center = (p + z * z / (2 * n)) / denom
    half = (z * sqrt(p * (1 - p) / n + z * z / (4 * n * n))) / denom
    return (max(0.0, center - half), min(1.0, center + half))
```

### 3.3 필요 표본수 n

목표: 95% CI의 반폭 `E`를 만족하는 최소 n. 가장 보수적인 `p̂ = 0.5`(분산 최대) 기준으로
정규근사 표본수 공식을 쓴다.

```
n ≳ z² / (4 · E²)
```

| 목표 반폭 E | 필요 n (p̂=0.5 기준) |
|---|---|
| ±10.0%p | 97 |
| ±7.0%p | 196 |
| ±5.0%p | **385** |
| ±3.0%p | 1,068 |
| ±2.0%p | 2,401 |

계산: `E = 0.05` → `n ≳ 1.959964² / (4 × 0.05²) = 3.8415 / 0.01 = 384.2` → **385**.

`p̂`가 0.5에서 멀면 실제 필요 n은 더 작다 (`n ≳ z²·p̂(1−p̂)/E²`).
예: `p̂ ≈ 0.2`, `E = 0.05` → `n ≳ 246`.
운영 기준은 **채널당 n ≥ 385** 를 목표로 하되, 예산 제약 시 채널별 예상 `p̂`로 개별 산정하고
그 사실과 실제 n을 리포트에 명시한다.

**n의 구성**: `n = questions × repetitions × |search_modes|`.
예) 질문 100개 × 반복 2회 × (검색 ON/OFF) = 400.
`supports_search_toggle: false`인 채널(Perplexity, 네이버, AI Overviews)은 `|search_modes| = 1`이므로
같은 n을 채우려면 질문 수나 반복 수를 늘려야 한다.

### 3.4 보고 형식 (강제)

```
❌ 금지:  "MR 33%"
✅ 정본:  "MR 33.0% (95% CI 28.5%–37.8%, n=400, Wilson)"
```

업계 전체가 점추정만 표기한다. 구간을 붙이는 순간 신뢰도의 격이 달라지고,
동시에 **"n=40으로 잰 33%"를 팔 수 없게 된다.** 그게 이 규칙의 요점이다.

## 4. 개선 유의성 검정 — two-proportion z-test

"MR이 35.4% → 40.6%로 올랐다"는 주장은 검정 없이는 의미가 없다.
반드시 **Matched Cohort**(동일 질문 세트 × 동일 채널 × 동일 검색 모드) 위에서만 비교한다.

### 4.1 공식

기준 시점 `(x₁, n₁)`, 비교 시점 `(x₂, n₂)`, `p̂₁ = x₁/n₁`, `p̂₂ = x₂/n₂`

```
             x₁ + x₂
p̂_pool  =  ───────────
             n₁ + n₂

                    p̂₂ − p̂₁
z  =  ─────────────────────────────────────────
       sqrt( p̂_pool (1 − p̂_pool) (1/n₁ + 1/n₂) )

p_value = 2 · (1 − Φ(|z|))        (양측 검정)
```

`α = 0.05`에서 `|z| > 1.96` 이면 유의. 결과는 `comparison.mr_significance[]`에 기록한다.

```python
from math import sqrt, erf

def two_proportion_z(x1: int, n1: int, x2: int, n2: int) -> tuple[float, float]:
    p1, p2 = x1 / n1, x2 / n2
    pool = (x1 + x2) / (n1 + n2)
    se = sqrt(pool * (1 - pool) * (1 / n1 + 1 / n2))
    if se == 0:
        return (0.0, 1.0)
    z = (p2 - p1) / se
    p_value = 2 * (1 - 0.5 * (1 + erf(abs(z) / sqrt(2))))
    return (z, p_value)
```

### 4.2 운영 규칙

1. **유의하지 않으면 "개선"이라고 쓰지 않는다.** `significant = false`이면 리포트 문구는
   "변화가 관측되었으나 통계적으로 유의하지 않음 (p = 0.18)"이다.
2. 다중 비교 보정: 6채널을 동시에 검정하면 우연히 하나가 유의할 확률이 커진다.
   채널별 결론을 낼 때는 Holm–Bonferroni 보정을 적용하고, 보정 적용 여부를 명시한다.
3. 모델 버전이 조용히 바뀌면 시계열이 단절된다(내부 분석 §8, 비공개).
   `series_break = true`인 구간을 가로지르는 개선 주장은 금지한다.

## 5. 프록시 격차 δ — 저가 트래킹 모델의 대가

### 5.1 문제

주간 트래킹을 플래그십 모델로 돌리면 원가가 감당되지 않는다
(채널당 n≈385 × 6채널 × 주간). 그래서 `channels.yaml`은 채널마다
`tracking_model`(주간·저가)과 `calibration_model`(월간·플래그십)을 분리한다.

**하지만 저가 모델과 플래그십 모델의 MR은 같지 않다.** 다른 모델이므로 당연하다.
이 차이를 숨기고 트래킹 수치를 "ChatGPT의 MR"이라고 파는 것은 부정확한 보고다.

### 5.2 정의

동일 질문 세트·동일 검색 모드에서 같은 기간에 두 모델을 호출해:

```
δ_c = MR_c(tracking_model) − MR_c(calibration_model)
```

- 부호를 유지한다. `δ > 0`이면 저가 모델이 브랜드를 과다 언급하고 있다는 뜻이다.
- 캘리브레이션 표본은 트래킹보다 작아도 되지만 `n ≥ 100`을 하한으로 한다.
- `δ`의 유의성은 §4의 two-proportion z-test로 검정한다.

### 5.3 공시 의무 (강제)

1. 모든 리포트의 `plane_a.proxy_gap[]`에 채널별 `δ`, 두 모델 id, 캘리브레이션 n, 측정일,
   유의 여부를 기록한다. **API 보유 채널(chatgpt, gemini, claude, perplexity) 4개는 필수.**
2. `api_available: false`인 채널(naver_ai_briefing, google_ai_overviews)은 모델 선택 개념이
   없으므로 δ 산출 대상에서 제외하고, 대신 **수집 방식(스크래핑/수동 캡처)을
   `limitations`에 명시**한다.
3. `|δ| > 0.05` 이고 유의하면 리포트 본문에 경고를 노출한다:
   > "본 채널의 주간 수치는 `gpt-5-mini` 기준이며, `gpt-5` 대비 +6.2%p 과다 추정됩니다(n=120, p=0.01).
   > 절대 수준 해석 시 이 격차를 감안하십시오."
4. `δ`는 **시계열 비교에서는 상쇄된다** (같은 트래킹 모델끼리 비교하므로).
   따라서 δ가 커도 "개선 추세" 판정은 유효하다. 무효가 되는 것은 **절대 수준 주장**뿐이다.
   이 구분을 리포트에 명시한다.
5. 캘리브레이션 주기: 월 1회. 모델 제공자가 버전을 갱신하면 즉시 재측정한다.
