# 신뢰도 공시 (Reliability Disclosure)

버전 **1.0.0** · 2026-09-18

## 1. 왜 이 절이 있는가

AEO 도구는 사이트에 점수를 매긴다. 그 점수로 고객은 돈을 쓰고 우선순위를 정한다.
그런데 **"다시 재면 같은 점수가 나오는가" 를 공시하는 도구가 없다.**

재현성을 모르는 점수는 해석할 수 없다. 재측정에서 3점이 올랐을 때 그게 개선인지
잡음인지 판별할 방법이 없기 때문이다. 점수를 파는 쪽이 그 판별 근거를 제공하지 않으면,
개선 주장은 검증 불가능한 주장이 된다.

이 절은 **AVR 구현이 자기 재현성을 어떻게 재고 어떻게 공시하는가**를 규정한다.
숫자를 규정하지 않는다 — 어떤 값이 나오든 그 값을 **측정하고 공시하는 것**이 요건이다.

> 이 문서는 자기 도구를 칭찬하는 자리가 아니다. 재현성이 낮게 나온 구현이 그 값을
> 공시하는 것은 적합하고, 재지 않은 구현은 값이 어떻든 부적합하다.

## 2. 변동을 셋으로 분해한다

재측정에서 점수가 달라졌을 때 원인은 셋이고, **뭉치면 영영 못 가른다.**

```
총 변동 = ① 채점 계층      + ② 시간 의존        + ③ 관측 계층
          같은 원문          같은 원문, 다른 날    재취득
          0이어야 한다       공시 대상            잡음 바닥
                                              + 대상의 실제 변화
```

③에는 "우리가 흔들린 것" 과 "사이트가 변한 것" 이 섞인다. §5 가 그것을 가른다.

## 3. 세 측정

### 3.1 결정성 (Determinism) — 필수, 값이 정해져 있다

같은 원문을 같은 rubric·같은 날짜로 두 번 채점하면 **완전히 같은 결과**가 나와야 한다.

| | |
|---|---|
| 입력 | 저장된 응답 원문 (재취득 금지) |
| 절차 | 동일 입력으로 채점을 2회 이상 실행 |
| 지표 | 다른 항목 수 / 비교한 항목 수 · 점수 최대 \|Δ\| |
| **요건** | **0 이어야 한다** |

0이 아니면 공시할 숫자가 아니라 **고칠 결함**이다. 흔한 원인: 집합·사전 순회 순서에
의존하는 "앞에서 N개" 표본, 시각 의존(§3.2 로 분리해야 한다), 난수, 병렬 실행 경합.

**이 측정은 원문을 저장하는 구현만 할 수 있다.** 원문을 안 남기는 구현은 자기 채점이
결정적인지 증명할 방법이 없고, rubric 이 바뀔 때마다 대상 서버를 다시 때려야 한다.

### 3.2 시간 의존 (Time sensitivity) — 공시

일부 항목은 "오늘" 을 입력으로 쓴다(갱신 주기, 신선도, 연도 상한 등). **같은 원문이라도
다른 날 채점하면 점수가 달라질 수 있고, 그건 결함이 아니라 성질이다.**

| | |
|---|---|
| 절차 | 같은 원문을 `now = 측정일 + {7, 30, 90}일` 로 재채점 |
| 지표 | 시점별 점수 중앙값 · 최대 \|Δ\| · 움직인 항목 id |
| **요건** | 값을 공시한다. 리포트에 **"측정 후 N일 경과 시 유효 범위"** 로 옮긴다 |

공시하지 않으면 고객이 "아무것도 안 고쳤는데 왜 점수가 변했나" 를 묻고, 그때 답할
근거가 없다.

### 3.3 재현성 (Test–retest) — 공시

같은 대상을 **짧은 간격으로 다시 취득해** 채점한다.

| | |
|---|---|
| 표본 | **선정 규칙을 실행 전에 공시한다.** 점수 전 구간이 들어가게 한다 |
| 간격 | 같은 날, 짧게. **길게 잡지 않는다** — 간격이 길수록 대상이 변해 재현성이 부풀려지거나 왜곡된다. 다만 CDN 이 같은 바이트를 그대로 돌려주는 구간은 피한다 |
| 지표 | 항목 일치율 · 점수 \|Δ\| 의 **중앙값·최대·상위 5%** |
| **요건** | 값을 공시한다. §4 의 통계 처리를 따른다 |

**평균을 쓰지 않는다.** 한 대상이 크게 튀면 평균이 그것을 숨긴다.

**표본을 결과를 보고 바꾸지 않는다.** 선정 규칙을 먼저 공시하는 이유가 이것이다.

## 4. 통계 처리 — 점추정을 단독으로 내지 않는다

항목 일치율은 비율이므로 신뢰구간을 붙인다. 그리고 **한 대상 안의 항목들은 독립이
아니다** — 한 사이트가 흔들리면 여러 항목이 함께 흔들린다. 독립을 가정한 구간은
실제보다 좁게 나온다.

```
DEFF  = 1 + (k − 1)·ρ          k = 대상당 항목 수
n_eff = n / DEFF
```

**요건**: 일치율을 공시할 때 **n · n_eff · ρ 를 함께 적는다.** ρ 를 관측에서 추정하지
않았다면 사용한 고정값과 그 선택을 명시한다.

> 이 규정은 `plane-a-visibility.md` 의 클러스터 보정과 같은 규칙을 **도구 자신에게**
> 적용한 것이다. 고객의 비율에 구간을 요구하면서 우리 비율은 맨값으로 내는 것은
> 일관되지 않는다.

## 5. 재현성만 높은 자를 배제한다 — 판별력 대조군

늘 같은 값을 뱉는 자는 완벽히 재현되지만 아무것도 재지 않는다. **재현성 수치는
반드시 판별력 근거와 함께 공시한다.**

| 최소 요건 | |
|---|---|
| **분포** | 코호트에서 점수의 범위와 표준편차. 자가 대상을 가르는가 |
| **변화 감지** | 대상이 실제로 변했을 때 점수가 따라 움직인 사례 |
| **교란 분리** | 두 회차의 **원문을 바이트 단위로 비교**한다. 원문이 같은데 점수가 다르면 **100% 구현 탓**이고, 원문이 다르면 대상 변화가 섞인 것이다 |

세 번째가 이 절에서 가장 중요하다. 원문 비교 없이는 "우리가 안 흔들렸다" 와 "대상이
안 변했다" 를 구분할 수 없고, 구분하지 못하면 재현성 수치는 아무것도 보증하지 않는다.

**변화 감지 사례를 보고할 때는 그 변화 중 구현 자신의 변경분을 분리한다.** 수집기를
추가한 뒤의 점수 상승을 대상의 변화로 적으면 그건 자기 기여를 대상의 개선으로 파는 것이다.

## 6. 공시 형식

구현은 아래를 **함께** 낸다. 하나라도 빠지면 이 절을 만족하지 않는다.

```
결정성      : 불일치 N / 비교 M (요건: 0)
시간 의존   : +7일 ±X · +30일 ±Y · +90일 ±Z (움직인 항목 id)
재현성      : 항목 일치율 P% [lo, hi]  n=N · n_eff=E · ρ=R
              점수 |Δ| 중앙값 A · 최대 B · 상위5% C  (대상 K곳, 간격 T)
판별력      : 코호트 점수 범위 [min, max] · σ
측정 일자   : YYYY-MM-DD · rubric 버전 · 구현 식별자
```

재현성을 잰 **대상 수와 간격**을 반드시 적는다. 8곳 10분과 200곳 1주는 다른 주장이다.

## 7. 적합성 수준과의 관계

`CONFORMANCE.md` 의 수준에 다음을 더한다.

| 수준 | 신뢰도 요건 |
|---|---|
| Level 1 (Scoring) | **§3.1 결정성**. 산식 구현이므로 같은 입력에 같은 출력은 최소 요건이다 |
| Level 2 (Assessment) | Level 1 + **§3.2·§3.3 공시** + §5 판별력 근거 |
| Level 3 (Measurement) | Level 2 + Plane A 프로빙의 재현성 (반복 k회의 채널별 변동) |

**공시 없이 수준을 주장할 수 없다.** 값이 나쁜 것은 적합성 문제가 아니지만, 재지 않은
것은 적합성 문제다.

## 8. 참조 구현의 실측 (2026-09-18)

아래는 **요건이 아니라 예시**다. 다른 구현의 값은 다를 수 있고, 달라도 된다.

```
결정성      : 불일치 0 / 692 항목 (28 대상, 네트워크 0건)
시간 의존   : +7일 0.0 · +30일 최대 1.2 · +90일 최대 1.6   (움직인 항목: P5-03)
재현성      : 항목 일치율 100.00% [80.14%, 100.00%]  n=217 · n_eff=16 · ρ=0.5
              ARS |Δ| 중앙값 0.00 · 최대 0.00 · 상위5% 0.00   (8곳, 10분 간격)
판별력      : 코호트 27곳 ARS 범위 [29.0, 66.0] · σ 8.1
측정 일자   : 2026-09-18 · rubric 1.9.0
```

교란 분리(§5): 두 회차 사이 **원문 바이트가 상당히 달랐다** — 한 대상은 관측 58건 중
29건만 동일했고 다른 대상은 55건 중 32건이었다. 그럼에도 점수는 완전히 같았다.

**이 측정이 말하지 않는 것**: 재현성은 "같은 답을 낸다" 이지 "옳은 답을 낸다" 가 아니다.
ARS 가 실제 AI 인용을 예측하는지(타당도)는 별개이며 `scoring.md` §2.1 이 그 상태를 적는다.
사람 판정(`check: manual`) 항목의 판정자 간 일치도(κ)는 아직 측정되지 않았다.
